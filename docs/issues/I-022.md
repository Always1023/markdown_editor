# I-022 打包瘦身：asar 去重复依赖 + 语言包裁剪

> 类型：重构 · 批次：B6 · 分支：I-022-slim-package · 整单验收方式：模型验收（行为不变）
> 关联：I-020（打包）、I-021（白屏修复，本分支叠于其上）

## 三层目标

- **意图**：一个本地 Markdown 编辑器不应携带 150MB 安装包——体积是产品观感的一部分，用户第一眼就问「这软件怎么这么重」。
- **行为**：安装包 / portable 体积显著下降；应用功能行为不变（编辑、文件监听、语言包中英可用）。
- **机制**：①electron-vite 主进程只把 chokidar 打进 bundle（`externalizeDepsPlugin({ exclude: ['chokidar'] })`），其余依赖维持外部化——渲染端依赖已由 vite 全量打进 out/renderer；②electron-builder `files` 排除 `node_modules/**`（不再把 64 个生产依赖重复塞进 asar）；③`electronLanguages` 只留 en-US / zh-CN（55 种语言包 → 2 种）；④删除 3 个未被引用的依赖（cmdk 移除；tw-animate-css、katex 复核后保留——main.css 有 `@import` 引用）。

## 过程记录

- **目标**：asar 里去掉 node_modules 重复；**现状**：electron-builder 把生产依赖照单全收进 asar（渲染端其实已由 vite 打进 out/renderer，依赖被装两遍）。**试错**：把 chokidar re-include 回 asar——pnpm 符号链接（junction）导致 glob 匹配 0 个文件；删除 externalizeDepsPlugin 想让 chokidar 进 bundle——electron-vite 对 main 有内建外部化（不看插件，直接外部化 package.json `dependencies`），bundle 里仍留 `require("chokidar")`，打包版报「Cannot find module」；用 `include: ['chokidar']`——语义反了，include 是「只外部化这些」。**答案**：`externalizeDepsPlugin({ exclude: ['chokidar'] })` = 外部化所有依赖除了 chokidar → chokidar 进 bundle；electron-builder `files` 排除 node_modules。两个工具的「自动包含生产依赖」行为对齐在同一个约定上：主进程 bundle 自带运行时依赖。
- 体积变化：安装包 156MB→102.7MB（-34%）；asar 306MB→约 64MB；win-unpacked 666MB→378MB；语言包 55 种→2 种。Electron 基座（exe + dll ≈ 274MB）不可再减。
