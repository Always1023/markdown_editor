## 目标
- 意图：想让迁移件的文件读写调用打到真实磁盘（目标）；现在 window.api.fs 与 runtime files.* 都没有主进程实现，触达即抛错（现状）；不做则保存 / 打开 / 图片落盘全部无法工作，产品读不了文件（代价）
- 行为：渲染端经 window.api.fs.* 与 window.api.runtime.call（files.* / clipboard.saveImageAsTempFile / status.get / layout.*）发起的调用由主进程真实执行；writeFile 对已存在文件走 writeIfUnchanged CAS（AC-04）；未实现的通道保持抛错
- 机制：electron/main ipcMain.handle 按 fs 子集逐个接线；runtime.call 按 method 名路由到本地文件服务（本机即主机，无远端）；路径校验（防越权目录）沿用 shared 的磁盘前置条件

## 过程记录
- AC-02 澄清：tsconfig.node.json 的 include 本就含 src/shared / src/lib（main 进程共享双端纯逻辑层），electron/main 经 `@/shared/` 引用类型与纯函数不违反隔离（隔离对象是渲染端组件 / store）。
- 拷入 Orca main 侧 local-file-io 全目录（writeIfUnchanged 核心：writeLocalTextFileWithDiskPrecondition / replaceLocalFileBytesIfUnchanged / 路径包容 / symlink 守卫）+ 依赖的 shared 补件（keyed-serialized-operations、map-with-concurrency、windows-retry-file-operations、filesystem-rename-collision、definitive-filesystem-absence、image-file-signature、wsl-paths）+ main 侧辅助（destination-serialized-local-rename、wsl-unc-drive-fs-path、local-log-tail-reader）。
- 越权防线：MARKDOWN_EDITOR_ROOTS 环境变量（分号分隔多根）声明工作根，requirePathInWorkRoots 对每次文件操作做根内校验；dev 默认根为 cwd。
- runtime files.* 参数沿用 Orca 远端语义（{worktree:'id:xxx', relativePath}）；主进程以 worktrees:register 注册表（worktree-roots.ts）解析根路径，未注册即拒绝。
- 通道面：fs:readFile/stat/pathExists/readDir/readFileChunk/writeFile/writeFileBytes/createFile/createDir/rename/copy/deletePath/listMarkdownDocuments/importExternalPaths + runtime:call（files.* / clipboard.saveImageAsTempFile / status.get / layout.unsubscribe）+ worktrees:register。
- 探针暴露并修复：MARKDOWN_EDITOR_ROOTS 按冒号分割会砍掉 Windows 盘符（C:\），改为仅分号分隔。
