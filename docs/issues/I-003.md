## 过程记录
- 迁移采用完整闭包策略：不做「15 文件 props 注入」改写，而是把编辑器子系统的依赖链整链拷入（store 切片 / runtime RPC / shared 模块），行为与 Orca 等价且更保真；round-trip 与 reconcile 测试全绿为证。
- 摘除执行为「链路摘除」：review-note-delivery 发送链、agent-launch / picker、structured-launch 持久化整链删除（边界留摘除注释）；review / diff-comment 的呈现层暂留（死代码，阶段 4 清理）。
- 测试基建：dom-setup 固定 process.platform=darwin（monaco model EOL 与 Orca mac/linux CI 语义对齐）；vitest 5 池配置拍平（execArgv 顶层）；testTimeout 60s（Windows 并行负载余量）。
- runtime-rpc-call 从抛错桩恢复为 Orca local 路由（window.api.runtime.call）——blob 图片管线依赖它；environment 目标保持失败可见。
- compat store 的 setActiveWorktree 补齐 Orca 激活语义（stateTransition 求值 + patch 合并 + 激活面派生），restored-editor-owner-restart 测试由此通过；hydrateTabsSession 按 Orca tabs-session-actions 本地子集实现（跳过终端 / 浏览器 reconciliation）。
