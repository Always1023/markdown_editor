## 目标
- 意图：想让 demo 编辑真实磁盘上的 Markdown 文件（目标）；现在文档驻内存、Ctrl+S 只更新 state（现状）；不做则「编辑器能保存」这一最小产品闭环不存在（代价）
- 行为：启动时打开工作目录下的 welcome.md（无则创建示例文档）；编辑 → 300ms 防抖 → 自动保存 / Ctrl+S 即时保存走 writeIfUnchanged 写盘；外部程序修改该文件 → 磁盘变更事件 → 编辑器显示外部修改横幅（不静默覆盖）
- 机制：组装层调用已迁移的 save / flush / autosave 链（pending-flush / stale-view-edit / discard-epoch 语义随内核生效）；watch 事件接 store 的磁盘基线更新

## 过程记录
- **装配点**：不新造保存逻辑——组装层直接接已迁移链：attachEditorAutosaveController（save queue + CAS 前置 + 自写登记 + dirty 扫描）+ setEditorDraft / markFileDirty + requestEditorFileSave（Ctrl+S）+ markFileChangedOnDisk（外部标记）。探针复用 editor-autosave-controller-test-fixture 的 store 构造（真实 editor slice + 缓冲中间件），window.api.fs 直连 electron/main 的本地实现（CAS / 越权语义与运行时一致）。
- **读盘竞态**：Orca parcel `subscribe` 返回即监听生效；demo 装配同样在 ready 语义内取基线（I-008 修复过 chokidar ready 前写盘被初始扫描吞掉的问题）。
- **横幅**：全量 ExternalFileChangeBanner（比对对话框 / undo toast / telemetry）牵入尚未接线的面板模块链（首次把 DiffViewer / github / toggle-group 等死代码拉进 tsc program，暴露 10 个既有类型缺口）。demo 期用轻横幅内联（keep / use-disk 两动作与 keepTabEditsOverExternalChange / reloadTabContentFromDisk 同语义最小面），阶段 3 外壳替换；顺手拷入缺失的 ui 原语 toggle.tsx（save-disk-precondition 的 type import 链上活文件）。
- **I-006 demo 渲染测试适配**：App 装配从内存改为真实文件 IO 后，app-demo-render.test.tsx stub window.api（fs 直连主进程实现 + 临时工作目录）；修复 spread 重建 window 断裂 happy-dom document 关联的问题（只挂 api）。
- **dev 冒烟**：MARKDOWN_EDITOR_ROOTS 指向临时目录起 pnpm dev——窗口启动、welcome.md 落盘成功、进程无崩溃后清理。
