## 目标
- 意图：想按场景选编辑方式——富文本所见即所得、纯源码、只读预览（目标）；现在只有 rich（现状）；不做则源码党与分享场景缺席（代价）
- 行为：工具切换 rich / source / preview 三模式；source 用 Monaco（动态 import，AC-08）展示原始 md，可直接编辑写盘；preview 只读渲染；往返内容一致
- 机制：markdown-preview 渲染树（已迁移）+ monaco-editor 0.55.1（动态 import）+ store editorViewMode

## 过程记录
- **preview 渲染树悬空引用（待决摘除边界的落点）**：目标＝preview 走迁移的 markdown-preview 渲染树；现状＝review 呈现层摘除后，渲染树 / surface / viewport 链上仍引用已删的 8 个 review 模块 + 2 个 native-chat 引用模块 + ui/virtualized-list，vite 解析失败（tsconfig include 按导入链收录，此前未暴露）。试错＝绕开 MarkdownPreview 直接用 react-markdown（丢弃迁移成果，否）。答案＝按摘除决策写 no-op 适配层（`markdown-preview/review/*` 8 个 + `native-chat/selection-quotes/*` 2 个，恒等 / 恒 null / 恒 no-op，每文件头注明摘除缘由）；`ui/virtualized-list.tsx` 从 Orca 逐字迁移两个自包含工具函数（VirtualizedList 组件本体不迁）。效果：preview 输出真渲染树（A2 过），批注 / 聊天 UI 不出现。这兑现了看板「摘除边界」待决项的呈现层部分。
- **Monaco 真渲染在 happy-dom 不可测**：A1 首版用真 Monaco——TextMate wasm fetch 失败降级 Monarch 后仍 30s 超时（worker 创建在 vitest 下挂起）。试错＝等待更久 / 换查询（否）。答案＝source 探针改装配级 mock（textarea 桩，value/onChange/onSave 同契约，vi.mock 拦动态 import）；「Monaco 真渲染」的证明拆给 AC-08（构建产物 `MonacoSourceEditor-*.js` 独立 chunk 存在）+ A6 人验残差（真机三模式观感）。
- **readOnly prop 位置**：@monaco-editor/react 的 readOnly 在 options 里，不是顶层 prop（typecheck 抓出）。
- **已知边界**：模式切换按条件渲染整棵编辑器（rich↔source/preview 重挂），滚动位置不跨模式保留——A6 人验看的就是这一点是否可接受；多 buffer 化（共享滚动 / 光标）属阶段 4 后深化。
