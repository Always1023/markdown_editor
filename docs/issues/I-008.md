## 目标
- 意图：想让编辑器感知磁盘上的外部修改（目标）；现在 watchWorktree / onFsChanged 无实现，外部编辑器改文件后应用毫无反应（现状）；不做则外部修改横幅（I-009）没有事件源，用户可能覆盖他人改动（代价）
- 行为：watchWorktree(path) 后该目录下的创建 / 修改 / 删除 / 重命名以 onFsChanged 载荷推送渲染端；unwatchWorktree 停止；重复 watch 幂等
- 机制：主进程 chokidar watcher + 事件映射为 Orca FsChangedPayload 形状；防抖合并瞬时风暴；容量上限（目录数）防泄漏；Windows 路径语义与 Orca watcher 本地子集一致

## 过程记录
- **目标**：watch 后外部修改以 FsChangedPayload 推渲染端。**现状（试错）**：首版探针超时——writeFile 在 chokidar `ready` 前完成，初始扫描（ignoreInitial:true）把新文件吞掉，只剩 awaitWriteFinish 残余的 change（kind 误为 update）。**答案**：subscribeLocalWatcher 等 `ready` 再返回（订阅返回即 watch 生效，与 Orca parcel `subscribe` 语义一致）；先占位进 watchedRoots 再等 ready，等待期间 unwatch 走 cancelled 检查防泄漏。
- Orca watcher 的复杂度集中在远端形态（WSL 子进程 / generation / removal gate / capacity retry），本地子集收敛为单文件 fs-watch.ts：rootKey 单例幂等、listeners 按窗口 id 区分、空即 teardown、双窗防抖（75ms leading / 100ms interval，shared 模块 filesystem-watch-batch-window.ts）、5000 事件上限改发 overflow、12 个高 churn 目录排除（.git / node_modules 等）。
- sender 抽象成 WatcherSender 接口（WebContents 结构兼容），探针注入 mock——沿用 Orca filesystem-watcher-test-sender 的形状，不依赖 electron 运行时。
- handleSafe 签名扩为 (event, payload) 以取 event.sender；全部 handler 参数统一补 (_event, p)。
- **无关发现**：全量测试默认并发下，长耗时测试（markdown-preview-table-chunks 单跑 6.2s）被资源竞争拖超时偶挂（两轮全量各挂一个不同文件、单跑均过）；`--maxWorkers=2` 稳定全绿。已记看板想法，不在本 issue 处理。
