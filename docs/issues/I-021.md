# I-021 · bug · 打包版首启白屏修复 + 免安装 portable 产物

**批次**：B5 · **关联**：I-020（人验打回）· **分支**：I-021-portable-white-fix

## 三层目标

**意图**：成品在人的真机上双击就能用，不白屏；并且有不装就能跑的版本。

**行为**：安装版 / portable 版普通启动（无调试参数）出现编辑器界面；渲染进程崩溃或主框架加载失败时自动恢复并有日志可查；新增单文件 portable exe 免安装产物。

**机制**：`app.disableHardwareAcceleration()`（文本编辑绘制不依赖 GPU 合成，稳定性优先）+ `did-fail-load` 主框架重试（≤3 次）+ `render-process-gone` 自动 reload（≤3 次）+ 主进程生命周期写 `userData/main.log`（失败可见可行动）；electron-builder win targets 增加 `portable`。

**bug 三要素**：
- 期望行为：双击安装版 / portable exe → 编辑器界面出现。
- 实际行为：人首启安装版（oneClick 装完即启）只见白窗无内容（截图留本文件末尾备注）。
- 不修的代价：成品在真机上不可用，交付被拒。
- 复现：人报告 + 截图；本机 CDP 复跑 DOM 已挂载、界面完整渲染（不稳定复现）→ 指向首启时序（装完即启 + 杀软首扫大文件拖慢解析）或 GPU 合成失败，按工程手段一并堵死。

## 过程记录

- **观测先行**：CDP 连安装版复跑（diag-white-screen.cjs）→ readyState complete、body 19777 字符、contenteditable 存在、界面实拍完整；唯一 log.error 为 data:font woff2 解码警告（图标显示正常，非致命）。结论：DOM 与布局正常，白屏出现在人的首启而非稳定缺陷 → 按两种假设（首启时序 / GPU）做防御性修复。
- **GPU 决策门**：A4 实测软渲染打字延迟后再定 disableHardwareAcceleration 是否保留；若 p50 显著劣化（> 2× 或 > 50ms），改为「GPU 崩溃后下次启动自动降级」方案。
- **答案（A4 实测）**：软渲染 p50 = 6.65ms / max 23ms，比修复前 GPU 模式基线（p50 10ms，I-006 记录）还快——本机 GPU 合成路径开销更高，disableHardwareAcceleration 保留，零丝滑代价。
- **打包首跑失败一次**：NSIS 中途退出（Setup 只剩 161KB 存根、portable 未产出）；重跑 exit 0 全部产出——判定为暂时性文件占用（当时可能有残留进程），非配置问题。
- **A2 探针三轮修正**：①首版单次取值量早 ~500ms 误报 FAIL（main.log 证实恢复已生效）；②后台化脚本被进程组回收干扰 → 改自包含；③win-unpacked 新二进制首扫拖慢挂载，before-kill 单次取值又误报 → 改挂载轮询；最终 DOM 级 PASS（安装版 85088）+ 日志级 PASS（还原版 94088），变异检查以日志断言为判定面。
- **portable 首启慢**：单文件自解压 156MB，冷启动 ~30s 才出窗（第二次起走缓存快）——已告知人属正常，不是白屏。
- **真根因（长观察 4 分钟抓到）**：人实测「显示一会再白屏」复现为——启动后 ~16s 抛 `Error: Tooltip must be used within TooltipProvider`（Orca 迁移件 RichMarkdownLinkBubble / RichMarkdownTableControls / ui-dialog 共 4 处裸 Tooltip，依赖 Orca 全局 Provider 而本项目没有），React 无错误边界 → 整树卸载 → 白屏；进程不崩溃，main.log 无 renderer gone。此前所有探针只观察 8~15s，恰好躲过触发窗口——**观察时长不足是「复现不了」的原因**。
- **修复**：①四处裸 Tooltip 补包 TooltipProvider（与 RichMarkdownToolbarButton 既有模式一致，迁移件最小改写）；②新增 RootErrorBoundary 挂在 main.tsx 根——任何渲染错误显示可读错误 + 重新加载按钮，永不再白屏。

## 自验

- **A1 普通启动像素（无任何调试参数）**：`powershell -File scripts/verify-plain-launch.ps1`——portable（`dist/markdown_editor 0.1.0.exe`，156MB 单文件）实拍 `portable-plain.png`、安装版（静默重装后）实拍 `installed-plain.png`，两图均出现完整编辑器界面（文件树 / 工具栏 / welcome.md 内容）；portable 单文件 155,877,993 字节 > 50MB。
- **A2 渲染崩溃自恢复**：`node scripts/verify-renderer-recovery.cjs` → before-kill contenteditable=true → killed renderer pid 85088 → after-kill contenteditable=true → **RECOVERY PASS**；main.log：`renderer gone: reason=crashed exitCode=-1` → ~0.5s 内 `main frame loaded` + `window ready-to-show`。
- **A3 生命周期日志**：main.log 含 `app ready v0.1.0 (win32)` / `main frame loaded` / `window ready-to-show`（两次普通启动 + 崩溃恢复路径均落行）。
- **A4 软渲染延迟**：`node scripts/latency-probe.cjs 9226` → 20 字符全数入编辑器，p50 = 6.65ms / max 23ms ≤ 2×GPU 基线（10ms）且 ≤ 50ms。
- **A5 回归与构建**：`pnpm typecheck` exit 0；`pnpm build` exit 0；`pnpm package` exit 0（Setup 156,045,292 + portable 155,877,988 字节）；全量回归 406 passed / 0 failed / 4 skipped（I-021-regression.log）。
- 变异检查（实际运行）：把恢复条件改为恒 false → build + package → 杀渲染进程 → main.log 在 `renderer gone`（06:50:50.749）后**不再出现** `main frame loaded`（未变异两轮分别为 0.46s / 0.50s 内出现）→ 断言变红，探针咬住实现；`git checkout -- electron/main/index.ts` 还原后重打包，日志复现 `renderer gone` → 0.5s `main frame loaded`（07:03:28.593 → 29.093），PASS。
- 隔离与清理：探针启动的实例全部 Stop-Process 回收；userData/main.log 为应用自身产物（保留，属用户数据）。
