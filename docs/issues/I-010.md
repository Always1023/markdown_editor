## 目标
- 意图：想让粘贴的截图自动存进磁盘并在文档里引用（目标）；现在 blob 管线到 clipboard.saveImageAsTempFile / importExternalPaths 处断链（无主进程实现），粘贴失败静默（现状）；不做则「粘贴图片自动落盘」这一核心卖点不成立（代价）
- 行为：粘贴截图 → PNG 转换 → 主进程落临时文件 → importExternalPaths 拷入文档同目录 → markdown 引用替换为本地文件名 → 图片经本地读取通道显示
- 机制：内核管线（rich-markdown-blob-image-paste 等）已迁移并测试通过，本 issue 只接主进程两端（saveImageAsTempFile + importExternalPaths）与显示读取（local-image-src-reader 依赖的 fs 通道）；目录语义跟随 Orca（文档同目录）

## 过程记录
- **断点 1（主进程 envelope）**：runtime:call 直接返回裸结果，而渲染端 callRuntimeRpc 期待 RuntimeRpcResponse envelope（{ok, result}）——`clipboard.saveImageAsTempFile` 经 runtime-rpc-call 必炸（I-007 探针只验了 files.* 直调，未验 envelope 路径）。修复：ipc.ts 的 runtime:call 包 envelope（成功 {ok:true, result}，失败 {ok:false, error}）；探针 stub 同口径。
- **断点 2（import 来源校验）**：saveImageAsTempFile 落系统 tmp，I-007 的 importExternalPaths 对 sourcePaths 做工作根内校验 → 临时图被越权拒绝。修复：requireImportSourcePath 放行系统 tmp（该目录只承载本应用 saveImageAsTempFile 的产物；destDir 仍严格工作根内）。
- **命名对齐**：saveImageAsTempFile 命名随 Orca（orca-paste-<now>-<rand>.<ext>，detectImageFileSignature 判扩展）；A2 字面「pasted-N」与 Orca 语义冲突，走修订表。
- **探针环境**：happy-dom 下 window.api 只挂 api 字段（重建 window 断裂 document 关联，与 I-009 渲染适配同一教训）；blob URL 前缀必须挂 window.location.origin（collectOwnBlobImageSources 的自源判定）。
- 真机粘贴体验并入 I-006 A5 手感残差（issue 铺路说明已约定）。
